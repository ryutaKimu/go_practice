# 開発バックログ

1チケット = 1ブランチ = 1PR で進める。ブランチ名は `feat/MIN-012-place-order` の形式。

進め方は [../CLAUDE.md](../CLAUDE.md) の「チケットの進め方」を参照。

## ステータス凡例

`未着手` / `進行中` / `レビュー中` / `完了` / `保留`

## 現在の着手順（2026-09-01 時点）

担当者が Go 未経験のため、着手順を組み替えている。

1. **MIN-000 立ち上がり**（環境構築・コードリーディング）
2. **MIN-006b Product 集約** ← いまここ（レビュー中）
3. **MIN-011 商品一覧・検索API**
4. MIN-010 リポジトリ基盤（保留中）

MIN-010 はインターフェース・トランザクション・pgx が同時に来るため、
Go に慣れる前に着手すると詰まる。単純な SELECT だけで完結する MIN-011 を先に通し、
「リクエスト → SQL → レスポンス」を一度自分で書いてから戻る。

## 優先度の考え方

**MIN-020 と MIN-021 が本件の価値の中心。** 売り越しゼロ（R-01）が実現できなければ、
他がすべて揃っても案件として失敗になる。Sprint 2 に最も厚く時間を確保する。

逆に、優先度「希望」の機能（FR-106 商品一括登録、FR-308 部分キャンセル、FR-402 チャネル別在庫配分）は
バックログに積むだけで、Sprint 5 まで着手しない。必須要件の達成が確実になってから判断する。
